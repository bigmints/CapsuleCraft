# Архитектура и принципы Co-Thinker (Руководство для мейнтейнера)

Данный документ описывает устройство, философию и правила расширения модуля **Co-Thinker** в CapsuleOS (`src/engine/cothinker/` и `src/engine/offlineAi.ts`).

---

## 1. Философия и ключевые инварианты (Core Principles)

CapsuleOS позиционируется как **Zero-DB, Pure-MIME (RFC 5322), 100% локальное и приватное хранилище мыслей**. 
В отличие от большинства современных заметочников, Co-Thinker строится на принципах **«Честного ИИ» (Honest AI)**:

1. **Железный запрет на выдумывание чисел (Zero-Hallucination Numbers):**
   * Никакие цифры, проценты или метрики не генерируются наугад.
   * Все вычисления (средние, тренды, корреляции, аномалии) производятся **строго кодом** по реальным вложениям (CSV) или цитируются дословно из капсулы.
2. **Нулевая зависимость от сети и внешних серверов:**
   * Движок работает на 100% офлайн и одинаково выполняется как в веб-сборке (браузер / WebWorker), так и в нативном десктопном приложении (Tauri).
   * Не требуются API-ключи, запущенный Python, CUDA или внешние сервисы.
3. **Двуязычность по умолчанию (Bilingual RU / EN):**
   * Co-Thinker автоматически определяет язык капсулы (`detectTextLang`) и формулирует критику, советы и синтез на том же языке (русский или английский).
4. **Не поддакивать автору (Adversarial Opponent):**
   * Co-Thinker — это не льстивый чат-бот, а строгий редактор и спарринг-партнер, задача которого — найти слепые пятна, логические дыры и размытые формулировки до того, как идея столкнется с реальностью.

## 2. Структура модулей (`src/engine/cothinker/`)

Когнитивный движок организован как модульный **Линтер мышления (Cognitive Thought Linter)**:

```
src/engine/
├── cothinker/
│   ├── types.ts                        # Общие интерфейсы, определение языка и Unicode-регексы
│   ├── focusMatcher.ts                 # Обработка кастомного запроса пользователя (prompt)
│   ├── inspectors/
│   │   ├── vagueWordsInspector.ts      # Детектор размытых слов и неконкретных обещаний
│   │   ├── actionabilityInspector.ts   # Проверка наличия первого физического шага (next action)
│   │   ├── balanceInspector.ts         # Детектор «розовых очков» и абсолютных утверждений
│   │   ├── readabilityInspector.ts     # Детектор перегруженных предложений (>35 слов)
│   │   └── dataAnomalyInspector.ts     # Статистический поиск выбросов и плато через simple-statistics
│   └── index.ts                        # Точка сборки и реэкспорта
└── offlineAi.ts                        # Главный диспетчер (generateOfflineAiResponse, offlineAiResponse)
```

## 3. Детальное описание компонентов

### 3.1. `focusMatcher.ts` (Связка с запросом пользователя)
* **Проблема:** Ранее поле кастомного промпта в модалке `AiCoThinkModal` передавалось в функцию, но игнорировалось в коде.
* **Решение:** 
  * `matchPromptFocus(prompt, text, lang)` фильтрует стоп-слова запроса и классифицирует интент пользователя по доменам (`finance`, `deadline`, `risk`, `execution`).
  * Сканирует текст капсулы на совпадения.
  * **Обработка слепых зон:** если пользователь спросил про деньги/бюджет (`finance`), а в капсуле нет ни единого финансового термина, движок прямо предупреждает: *«Внимание: запрос касается финансов и бюджета, однако в тексте капсулы нет ни одного упоминания цен или расходов. Финансовая модель не описана.»*

### 3.2. Инспекторы мышления (`inspectors/`)

1. **`vagueWordsInspector.ts`:**
   * Находит фразы со словами-маркерами неопределённости (*«скоро», «в будущем», «значительно», «улучшить», «soon», «significantly», «optimize»*).
   * Выдаёт конкретный совет: заменить субъективное наречие на измеримую метрику или точную дату.
2. **`actionabilityInspector.ts`:**
   * Проверяет, есть ли в длинной заметке хоть один глагол физического действия (*«сделать», «протестировать», «созвониться»* и английские глаголы через библиотеку `compromise`) или чек-лист `[ ]`.
   * Предотвращает превращение заметок в бесполезную «чистую теорию».
3. **`balanceInspector.ts`:**
   * Ловит абсолютные формулировки (*«всегда», «никогда», «гарантированно», «always», «guaranteed»*), напоминая о граничных условиях.
   * Ловит «розовые очки»: если в тексте много слов успеха и выгоды, но ноль маркеров трения, рисков или буфера — предлагает провести мини-*pre-mortem*.
4. **`readabilityInspector.ts`:**
   * Находит предложения длиннее 35 слов и рекомендует разбить их на два простых тезиса.
5. **`dataAnomalyInspector.ts`:**
   * Использует математическую библиотеку **`simple-statistics`** (метод Тьюки: интерквартильный размах $Q_3 + 1.5 \times IQR$ и $Q_1 - 1.5 \times IQR$, медиана, стандартное отклонение).
   * Выявляет резкие скачки (выбросы) и застойные плато в CSV, формулируя выводы понятным человеческим языком без заумной терминологии.

### 3.3. Важная техническая деталь: `unicodeWordRegex`
В JavaScript стандартная граница слова `\b` **не работает для кириллицы** (поскольку `\w` включает только латиницу `[a-zA-Z0-9_]`).  
Для всех текстовых проверок в `types.ts` реализован хелпер:
```typescript
export function unicodeWordRegex(pattern: string): RegExp {
  return new RegExp(`(?<=^|[^\\p{L}\\p{N}])(${pattern})(?=$|[^\\p{L}\\p{N}])`, 'iu');
}
```
Он гарантирует корректную работу границ слов как для русского, так и для английского языка.

## 4. Как добавить новый инспектор (Инструкция для разработчика)

1. Создайте файл `src/engine/cothinker/inspectors/myNewInspector.ts`.
2. Реализуйте функцию инспекции, возвращающую массив `InspectorFinding[]`:
   ```typescript
   import { InspectorFinding, SupportedLang, detectTextLang } from '../types';

   export function inspectMyRule(
     text: string, 
     lang: SupportedLang = detectTextLang(text)
   ): InspectorFinding[] {
     // Ваша проверка...
   }
   ```
3. Экспортируйте инспектор в `src/engine/cothinker/index.ts`.
4. Подключите вызов в `generateOfflineAiResponse` внутри `src/engine/offlineAi.ts`.
5. Добавьте юнит-тесты в `src/engine/__tests__/cothinkerInspectors.test.ts`.
