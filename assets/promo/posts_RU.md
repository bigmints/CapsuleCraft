## 1. Telegram (канал) — с demo.gif

**Заметки, которые нельзя потерять: CapsuleCraft — база знаний из обычных .eml-файлов**

Большинство баз знаний держат ваши мысли в закрытой базе: умрёт приложение — умрёт и всё, что вы в него записали. CapsuleCraft переворачивает схему: одна страница = один настоящий файл `.eml` (RFC 5322). Его открывает Thunderbird, его находит `grep`, его диффает `git`, его синхронизирует Syncthing. Приложение можно удалить завтра — данные переживут его на десятилетия.

Что внутри:
■ блочный редактор: заголовки, задачи, коллауты, код, CSV-таблицы;
■ `[[вики-ссылки]]` с живым индексом обратных ссылок;
■ поиск Okapi BM25 по всему хранилищу — с оценками релевантности и сниппетами, кириллица понимается;
■ планирование: все задачи из заметок собираются в Agenda / Kanban / Gantt + экспорт в календарь (ICS);
■ треды как в почте — ответы это дочерние .eml с `In-Reply-To`;
■ офлайн Co-Thinker, который спорит с вашими тезисами без всяких API-ключей;
■ MCP-сервер: Claude, Cursor или любой агент может читать и искать вашу базу.

Ни базы данных, ни облака, ни аккаунтов, ни телеметрии — парсинг, поиск и ИИ работают локально. Нативная сборка на Rust + egui без браузерного движка: AppImage весит ~11 МБ.

### Мотивация

Инструменты для заметок принято мерить функциями. Я предлагаю мерить их иначе: что произойдёт с вашими записями, если проект завтра закроется? Для Obsidian ответ «ничего страшного» — Markdown читается где угодно. Для Notion и OneNote ответ заметно грустнее: проприетарная база, экспорт через боль, и ваши десять лет заметок привязаны к чужому серверу или бинарному формату.

CapsuleCraft доводит идею «данные переживают приложение» до логического предела: **одна страница = один файл `.eml`** — самое обычное письмо по RFC 5322, с MIME-частями для данных. Никакой своей базы данных нет вообще, ни SQLite, ни leveldb, ни реестра. Вся база знаний — это папка, которую вы можете открыть любым почтовым клиентом, прогнать через `grep`, положить в `git` и синхронизировать `rsync` или Syncthing. Приложение можно снести — данные не заметят этого.

### Что умеет v1.8.1

**Блочный редактор.** Заголовки, абзацы, чек-листы, коллауты, код, CSV-датагриды, аудиозаметки. Автосохранение, undo/redo, честный round-trip: всё, что вы видите, пишется обратно в `.eml` байт-в-байт совместимо с почтовыми клиентами. Это правило — «каждый байт должен проходить туда-обратно через почтовый клиент» — закреплено в коде как главный инвариант формата.

**Вики-механика.** `[[ссылки]]` парсятся из текста страниц, кликабельны, а индекс обратных ссылок («Linked from») строится живым. Переименование страницы переписывает все ссылки по хранилищу.

**Поиск.** Okapi BM25 по всему хранилищу: оценки релевантности, подсвеченные сниппеты, кириллический case-folding. «Похожие по смыслу» ранжируются tf-idf косинусом по тому же индексу — без единого сетевого вызова.

**Планирование.** Все блоки задач из всех заметок собираются в один слой: Agenda, Kanban с drag&drop, Gantt со стрелками зависимостей и защитой от циклов, календарь и экспорт RFC 5545 ICS. Фильтры общие: по тексту, статусу, приоритету, срокам, капсуле и тегу.

**Треды.** Ответ на заметку — настоящий дочерний `.eml` с `In-Reply-To`/`References`. Дерево рассуждений — это ровно то, что любой почтовый клиент умеет показывать нативно.

**Датасеты.** CSV/JSON едут как MIME-части и адресуются `Content-ID` — датагрид-блоки рендерят их таблицами. Таблица в заметке — это не волшебство внутри базы, а вложение, которое откроется в Excel.

**Импорт.** Перетащите `.eml` из Gmail/Outlook/Thunderbird в окно — импортируются байт-в-байт. Есть синхронизация по IMAP и миграция готового Obsidian-хранилища (`--import-obsidian`).

**Офлайн Co-Thinker и MCP.** Детерминированный локальный движок критикует ваши тезисы (расплывчатые формулировки, перекосы аргументации, аномалии в данных) — без API-ключей и без отправки мыслей в облако. А если нужен внешний агент — хранилище отдаётся по MCP: Claude, Cursor или любой MCP-клиент может читать и искать вашу базу.

### Нативный шелл

v1.5+ — это нативная сборка на Rust + egui, без браузерного движка. Никакого WebKitGTK/WebView2/Electron: AppImage ~11 МБ, зависимости — только glibc и X11/Wayland. Есть сборки под Windows (портативный zip) и macOS (arm64, ad-hoc подпись). Интерфейс на русском и английском. Запуск — мгновенный, стартует с пустым хранилищем и встроенным FAQ (F1): никаких демо-заметок, притворяющихся вашими данными.

### Честная таблица сравнения

| | CapsuleCraft | Obsidian | OneNote | Notion |
|---|---|---|---|---|
| Формат хранения | открытый `.eml` | Markdown + скрытые данные приложения | бинарные секции | облачная база |
| Читается без приложения | ✅ любой почтовый клиент, grep, git | ✅ | ❌ | ❌ |
| Полностью офлайн | ✅ по дизайну | ✅ | ⚠️ | ⚠️ |
| Аккаунт | ❌ никогда | ❌ (для платной синхронизации ✅) | ✅ | ✅ для синхронизации |
| Локальный детерминированный ИИ | ✅ Co-Thinker | ⚠️ плагины/облако | ⚠️ Copilot (облако) | ⚠️ облако |
| Реальные почтовые треды | ✅ In-Reply-To/References | ❌ | ❌ | ❌ |
| Размер установки (Linux) | ~11 МБ, без webview | ~100 МБ Electron | 100+ МБ | веб |
| Open source | ✅ MIT | ❌ | ❌ | ❌ |

Честно про слабые места: у Obsidian — экосистема плагинов, у OneNote — стилус, у Notion — совместное редактирование. CapsuleCraft сознательно у́же: локальное хранение, которому можно доверять десятилетиями. Известные ограничения не спрятаны в маркетинг, а лежат в LIMITATIONS.md: в нативном шелле пока нет исполнения кода и воспроизведения аудио, отслеживание папки — best effort, шифрования GPG пока нет.
